# Permanent No-Messenger Operating Rules

**OWNER DECISION: JEROME IS THE OWNER, NOT THE MESSENGER.** Specialists own their documentation and handoffs. Master Control owns coordination and cross-specialist decisions.

1. Every assistant starts by reading the current pointer, the complete foundational Master Bank H and all subsequent published Master Brain documents, plus relevant authority files and handoffs.
2. Every specialist maintains status: scope, source/build identity, work attempted, verified results, rejected attempts, owner approvals, unresolved blockers, and next steps.
3. Master Control records approved assignments in `MASTER_CONTROL.md`. Specialists retrieve them from GitHub rather than requiring Jerome to carry messages.
4. Specialists may publish status to their assigned record only with the applicable owner authorization and working write access. Master Control reads those records before coordination decisions.
5. Never claim automatic chat-to-chat communication. Shared records become current only after successful commit and read-back verification; reading them is an explicit action when a chat resumes.
6. Do not require Jerome to shuttle routine reports, instructions, ZIP details, or decisions. If write access is blocked, report the exact blocker and provide one complete handoff.
7. Preserve approved design locks, actual Android pixel authority, original references, rollback checkpoints, candidate classifications, and rejected attempts.
8. Never modify game files, merge builds, publish a Master Brain, generate art, or deploy without explicit applicable owner approval. A candidate does not become approved merely because code exists.
9. Prevent conflicts: inspect other specialist records and obtain Master Control coordination before touching shared systems.
10. Every future chat inherits the full-bank reading procedure and self-perpetuating continuity rule in the current published Master Brain; reproduce the complete continuity rule verbatim in successor handoffs and startup prompts.
11. Updating this coordination folder does not create a new Master Brain version or change `brain/current.json`.
