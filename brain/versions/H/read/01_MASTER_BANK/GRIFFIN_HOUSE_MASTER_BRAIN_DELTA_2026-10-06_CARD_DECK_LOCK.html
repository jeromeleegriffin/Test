1. DEFAULT NUMBERED DECK — LOCKED
Owner approved the latest worded ivory-card design as the DEFAULT numbered deck direction.

Default numbered-card face:
- warm ivory / cream card stock
- fine premium linen / air-emboss style texture
- one large bold number only
- number color uses the authoritative Griffin House gameplay palette
- written color word centered below the number: RED / GREEN / YELLOW / BLACK
- written color word is part of the default face, not a colorblind-only overlay
- thin restrained bronze/gold border
- clean premium finish
- current number/word spacing and relative scale approved as the target direction
- no second/small corner number
- no center emblem
- no distracting diamonds or heavy ornament
- core card face is to be built as a real asset/system, not as decorative CSS tricks

6. 16-CARD HAND CORRECTION — IMPORTANT
The prior assumption that the player's normal hand reaches 16 cards is wrong.
There is NO normal gameplay state with 16 cards in the player's hand.
Do not use 16-card hand overlap, tray width, card sizing, or progressive reveal as a design constraint.

The "Select 6 cards to discard" screen is a separate UI state that may temporarily display a larger card set. It is not the normal hand/tray and must be designed separately.

7. ACCESSIBILITY / COLOR WORD DECISION
The written color words on the DEFAULT numbered deck provide built-in redundant color identification for all players.
This means color identity is communicated by BOTH:
- the number's gameplay color
- the written word RED / GREEN / YELLOW / BLACK

Do not assume a separate line/pattern treatment is required for the default deck.
The existing game currently exposes a "Contrast" control that toggles a high-contrast state; any old colorblind/pattern behavior should be independently verified before changing or removing it.

8. 6 / 9 ORIENTATION CUE
Not locked.
Current preference is to avoid a heavy underline.
If actual runtime testing shows 6/9 ambiguity in rotated played cards, use only a very subtle cue (tiny line/tick/dot) that does not compete with the main number or color word.

9. RUNTIME DEPTH
Keep master face artwork clean.
Subtle card depth/shadow may be added at runtime to make cards read as physical objects above the felt.
Do not bake exaggerated drop shadows into the face art.

10. ASSET-FIRST GLOBAL RULE
Everything in the game should be built as real assets where practical.
CSS/runtime code should primarily handle placement, scaling, masking, clipping, reveal, shadow, animation, and integration—not act as the primary replacement for important artwork.
This applies especially to:
- table
- cards
- character art
- other major physical visual elements

11. ACTUAL-PIXELS RULE
Generated whole-game mockups are NOT runtime authority.
When proving these cards in the game:
- use the real runtime screenshot / actual pixels
- keep the existing game pixels untouched
- replace/composite only the intended card regions
- do not let image generation redraw the table, UI, avatars, Bid Box, Last Trick controls, or room

12. NEXT STEP
Build the production-quality master numbered-card asset/template from the locked default system, then derive the full numbered deck consistently from that master system.
After asset generation, verify readability in the real normal hand and in the separate discard-selection screen using actual runtime pixels.
